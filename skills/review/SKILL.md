# コードレビュー

ユーザーが指定したファイルまたは範囲のコードレビューを行う。

## 観点

特に指定がない場合、仕様・アーキテクチャ・挙動・可読性・保守性・運用性・
パフォーマンス・信頼性・セキュリティ・テスト・コメント・ドキュメントなど
一般的な品質観点を総合的にレビューする。

特にアーキテクチャや運用性は大きな視点が必要となり、見逃しがちなので注意。

## 手順

1. 問題点を洗い出し、一次リストを作成する。
2. 各問題点について、状況を慎重に確認し、実際に問題かを判断する（敵対的検証）。
3. 確認された問題の一覧を報告する。

問題点が一定数見つかったからと言って満足せず、取り逃しないように洗い出すこと。

ユーザーがマルチレビューを求めた場合、下記3つのサブエージェントを立てて並行でレビューし、
最後に結果をまとめて報告すること。

| エージェント | 担当観点 | 
| --- | --- |
| 正しさ       | 仕様・アーキテクチャ・挙動・信頼性 |
| 保守性       | 可読性・保守性・運用性・テスト・ドキュメント |
| セキュリティ | セキュリティ |

検証した結果問題ではなかった点はノイズになるので最終報告に含めないこと。
